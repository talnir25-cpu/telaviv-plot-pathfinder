## הבעיה

עבור ויצמן 33, פונקציית `parse-tabu-pdf` החזירה `floors: 4` בעוד שהמספר האמיתי שונה (לפי מקורות אחרים — נדל"ן הממשלתי / היתרי ת"א מצביעים על בניין אחר, ונראה גם בתצוגה ש־`8 יח״ד / 4 קומות` לא תואם למבנה בן 16 יח״ד הרשום בהיתרים).

## מקור הבעיה

הלוגיקה ב־`supabase/functions/parse-tabu-pdf/index.ts` (שורה 43, 70):

```
floors = הקומה הגבוהה ביותר המוזכרת בתת-חלקות + 1 (קרקע=0, א'=1, ...)
```

כשלים אפשריים עם הכלל הזה:

1. **קומת קרקע לא תמיד מאוכלסת בדירות** — אם בנסח אין דירה בקומת קרקע (חנויות/לובי), ה-AI עלול לדלג עליה ולספור רק מ-א' ומעלה, או להפך — להוסיף +1 שגוי.
2. **קומה א' = 1** בלבול: בעברית "קומה ראשונה" היא לפעמים מעל הקרקע (כלומר קומה שנייה פיזית). הפרומפט מניח מיפוי מסוים אך לא תמיד עקבי בנסחים.
3. **תת-חלקות = דירות בלבד** — חניות, מחסנים, גגות וקומות טכניות לא נספרים, ולכן הקומה הגבוהה ביותר ב"דירות" אינה הקומה הפיזית הגבוהה.
4. **גג / חדרים על הגג / מרתף** — לעיתים מופיעים תחת קומה מיוחדת ("גג", "מרתף") וה-AI מתעלם מהם או סופר אותם כ-0.
5. **הסכמה מגבילה את ה-AI** ל-tool יחיד בלי לחשוף את הקומות הגולמיות, ולכן אי אפשר לאמת מהיכן הגיע המספר.

עבור ויצמן 33, סביר שהנסח כולל תת-חלקות עד קומה ג' (=3), ה-AI החזיר 4, אבל הבניין בפועל גבוה יותר (היתרים מראים תהליך תמ"א 38 עם 16 יח"ד — מצביע על בניין קיים גדול יותר מ-8 יח"ד/4 קומות, או שהמספרים נשלפו מנסח של בניין סמוך/חלקי).

## תוכנית התיקון

### 1. שיפור הפרומפט וה־schema

ב־`supabase/functions/parse-tabu-pdf/index.ts`:

- להוסיף לסכמת ה־tool שדה גולמי `floorsDetected: { highestFloorLabel, lowestFloorLabel, hasGroundUnit, hasRoofUnit, hasBasement }` כדי שנוכל לבדוק/לאמת.
- לשנות את ההגדרה של `floors` כך שתכלול במפורש:
  - קומת קרקע נספרת כקומה תמיד (גם אם אין בה דירה — אלא אם הנסח מציין במפורש שאין קרקע).
  - קומת גג / חדר על הגג נספרת כקומה נוספת אם מוזכרת.
  - מרתף לא נספר במספר הקומות העל-קרקעיות.
- להחזיר גם `floorsRaw` (טקסטואלי) כדי שנציג בUI אינדיקציה למקור.

### 2. החזרת מטא־דאטה ל־UI

להחזיר בתגובה:
```json
{ "analysis": { ..., "floorsExplain": "קומות שזוהו: קרקע, א', ב', ג' + גג" } }
```

### 3. הצגה ב־PlotPicker

ב־`src/components/PlotPicker.tsx` (סביב שורה 254 ו־1241), כשמציבים את `existingFloors` מהניתוח, להציג tooltip/הסבר קצר עם `floorsExplain` כדי שהמשתמש יוכל לאמת ולתקן ידנית במידת הצורך.

### 4. אימות

לאחר הפריסה האוטומטית של הפונקציה, להריץ שוב את נסח ויצמן 33 ולבדוק את ה-payload החדש ב-Network. אם עדיין לא מדויק — סימן שהבעיה בנסח עצמו (נסח חלקי) ולא בלוגיקה, ונציין זאת למשתמש.
