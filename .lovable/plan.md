# שיפור זרימת השלב המקדים (PlotPicker)

המטרה: להפוך את הטופס מ"רשת של 10+ שדות שטוחה" למסע מודרך עם 3 שלבים ברורים — **זיהוי החלקה → אימות הנתונים הקיימים → פרמטרים תכנוניים** — כך שהמשתמש תמיד יודע מה הוא בוחן עכשיו ומה עוד חסר לפני "הפק דוח".

## 1. בעיות מרכזיות בזרימה הנוכחית

1. **סדר לא נרטיבי** — שטח מגרש מופיע לפני רוחב/עומק, אבל קווי בניין (שתלויים בממדים) מופיעים אחריהם; "שטח בנוי" מופיע אחרי "קומות" אבל הוא נשלף מאותו מקור.
2. **חוסר היררכיה ויזואלית** — `md:grid-cols-2` שטוח: שדה זיהוי (גוש) נראה זהה לשדה נגזר (תכסית מחושבת). אין הבחנה בין "מה שאתה מזין" ל"מה שהמערכת חישבה".
3. **רעש מטא-נתונים** — badges של מקור (`GovMap`, `אמינות בינונית`, `מאומת ידנית`) חוזרים 3 פעמים (יח"ד, קומות, שטח בנוי) ולוקחים יותר מקום מהערך עצמו.
4. **כפתור "אתר חלקה" נעלם אחרי הצלחה** — המשתמש לא יודע אם הזיהוי "נעול" או שאפשר לערוך.
5. **שדות אופציונליים מעורבים עם חובה** — רוחב/עומק/שנת בנייה הם best-effort, אבל מוצגים זהה ליח"ד וקומות.
6. **"מקורות נתונים (3/5 הצליחו)"** קבור בסוף — זה בעצם הסיגנל הכי חשוב לאמון בדוח.
7. **אין סיכום לפני שליחה** — לחיצה על "נתח" שולחת בלי תקציר של מה ינותח.

## 2. סדר מוצע (Three-Step Flow)

```
┌─ STEP 1 · זיהוי החלקה ─────────────────────────────┐
│  [כתובת] או [רובע + גוש + חלקה]                    │
│  ← תוצאה: כרטיס "החלקה שזוהתה" (כתובת, שטח, רובע) │
│    + מיני-מפה (thumbnail מ-PlotMap)                │
└─────────────────────────────────────────────────────┘
            ↓ (נפתח רק אחרי בחירת חלקה)
┌─ STEP 2 · המצב הקיים ──────────────────────────────┐
│  3 שדות בשורה: יח"ד | קומות | שטח בנוי             │
│  badge יחיד מאוחד מעל הקבוצה:                       │
│     "נשלף מ-GovMap + היתרי ת״א · אמינות בינונית"   │
│  שורת מטא: שנת בנייה | [קישור נדל״ן.gov]           │
└─────────────────────────────────────────────────────┘
            ↓
┌─ STEP 3 · פרמטרים תכנוניים (פתוח כברירת מחדל) ────┐
│  ממדי מגרש (רוחב × עומק)  ←  קווי בניין            │
│  ← תכסית מחושבת (תוצאה נגזרת, מודגשת כ-readonly)   │
│  שימור [switch] · הערות [textarea, מקופל]          │
└─────────────────────────────────────────────────────┘
            ↓
┌─ Sticky CTA bar ───────────────────────────────────┐
│  "ינותח: גוש 6111 חלקה 483 · 540 מ״ר · 8 יח״ד"     │
│  [הפק דוח היתכנות →]   [מקורות נתונים 3/5]         │
└─────────────────────────────────────────────────────┘
```

## 3. שינויים קונקרטיים בקוד (לפי קובץ)

**`src/components/PlotPicker.tsx`**

1. **לעטוף את הטופס ב-3 קטעים סמנטיים** (`<section>` עם רקע עדין `bg-muted/10` ו-`border-r-2 border-primary/40`), כל אחד עם כותרת קטנה "שלב 1 · זיהוי החלקה" וכו'. ה-grid השטוח (שורה 608) מתפצל ל-3 רשתות עצמאיות.

2. **כרטיס "חלקה מזוהה"** (אחרי בחירה מוצלחת) — מחליף את שדה "שטח החלקה" + תיבת `resolvedAddress`. מציג: כתובת · רובע · גוש/חלקה · שטח · thumbnail מ-PlotMap · כפתור "החלף חלקה" (איפוס). זה הופך לעוגן חזותי.

3. **לאחד badges של מקור** — במקום 3 badges כפולים על יח"ד/קומות/שטח, badge אחד מאוחד בכותרת קבוצת "מצב קיים":
   `<MetaBar source="GovMap + היתרי ת״א" confidence="medium" lastFetched="..." />`
   הפרטים-לכל-שדה עוברים ל-tooltip על אייקון `Info` קטן ליד התווית.

4. **לקבץ ממדי מגרש + קווי בניין + תכסית בקבוצה אחת** "גיאומטריה" (כי שלושתם מזינים את אותו חישוב). תכסית מוצגת כ-**מד תוצאה** (progress bar 0-100% עם הצללת תחום סביר 15-70%), לא כשדה.

5. **שינוי סדר שדות בתוך קבוצה 2** מ-`(יח"ד) → (קומות) → (שטח בנוי + תיאור ארוך)` ל-grid של 3 בשורה אחת עם תוויות קצרות, ותיאור משותף מתחת. שנת בנייה + קישור נדל״ן.gov עוברים לשורה משנית קטנה יותר.

6. **"מקורות נתונים" שדרוג מ-Collapsible תחתון ל-pill קליק-בייל ב-CTA bar** — `"3/5 מקורות הצליחו"` עם נקודה ירוקה/כתומה. לחיצה פותחת את אותו dialog.

7. **CTA Sticky bar בתחתית הכרטיס** (`sticky bottom-0 -mx-6 -mb-6 bg-background/95 backdrop-blur border-t`) שמציג תקציר טקסטואלי של מה שיישלח + כפתור ראשי. נותן ביטחון לפני לחיצה ומונע גלילה למעלה כדי לאמת.

8. **שדה הערות לכווץ ב-Collapsible** ("הוסף הערות לאנליסט (אופציונלי)") — כיום הוא תופס מקום למרות שרוב המשתמשים לא ממלאים.

9. **אנימציית מעבר בין שלבים** — `animate-in fade-in slide-in-from-bottom-2` כשנפתח שלב 2 אחרי זיהוי חלקה, כדי שיהיה ברור שמשהו השתנה.

## 4. הערות עיצוביות

- **טוקנים סמנטיים בלבד** (מ-`index.css`) — להחליף את `text-emerald-600 dark:text-emerald-400`, `text-amber-600` שמופיעים ב-CONFIDENCE_META/STATUS_ICON ב-`text-success` / `text-warning` שכבר מוגדרים ב-`KpiHeader.tsx`. כיום יש סטייה מהמערכת.
- **היררכיית טיפוגרפיה** — כותרת שלב `text-xs uppercase tracking-wider text-muted-foreground`, תווית שדה `text-sm font-medium`, ערך נגזר `text-lg font-bold tabular-nums`. כרגע הכל `text-sm`.
- **שדות auto-filled** — להוסיף `bg-emerald-50/40` עדין במקום רק badge "GovMap" — סיגנל פסיבי יותר. עריכה ידנית מנקה את הרקע (כבר קיימת לוגיקת `setGeometryAutoFilled(false)`).
- **גודל badges** — להוריד מ-`text-[10px]` ל-`text-[11px]` ולצמצם מ-3 badges בשורה ל-1 מאוחד; זה מנקה ~40% מהרעש החזותי.
- **קווי בניין + תכסית** — להציג כ-card אחד צמוד (לא 2 ב-grid), כי הם נקראים יחד.

## 5. מה לא לשנות

- לוגיקת השליפה (`runLookup`, `fetch-plot-geometry`, cache) — עובדת היטב.
- סכמת הטופס (`analysisInputSchema`) ושדות `AnalysisInput` — UI בלבד.
- ה-Dialog של "Raw" ושל מקורות — תוכן זהה, רק נקודת כניסה זזה.

## 6. סדר עדיפות מומלץ ליישום

1. (גדול, ערך גבוה) קיפול ל-3 שלבים + כרטיס "חלקה מזוהה" + Sticky CTA.
2. (בינוני) איחוד badges של מקור + tooltip למידע פרטני.
3. (קטן) טוקנים סמנטיים + auto-filled background + הערות ב-collapsible.
4. (אופציונלי) מד תכסית ויזואלי כ-progress bar.

מוכן להתחיל מאיזה שלב שתבחר — אם רוצים אפשר גם להוציא קודם 2-3 כיווני עיצוב מרונדרים לבחירה לפני הקוד.
